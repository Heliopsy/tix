What a source is, and what happens when you run it

A source is a name and a system. That is all you supply: the record holds no url, no file path and no credential, only those two and the cursor and status its own runs leave behind. Everything a run needs to reach the other system is read from the server's environment when the run starts, which is why no credential can reach a snapshot, an audit entry, an event or a log line.

Running one fetches records from that system, translates each through a mapping file, and creates or updates tasks in the project the mapping names. Imported tasks are ordinary tasks: nothing downstream treats them specially. They are attributed to a System actor rather than to you.

Every task an import touches gets an external reference recording the system, the identifier and url at the source, the version it was at, and when it was last synced. That reference is what makes a second run a refresh instead of a second copy.

Where a source's settings live

In environment variables on the machine running tix, named after the source. The name is upper-cased and every run of other characters becomes a single underscore, so a source called ops export is configured through {{envName .Data.Prefix "OPS_EXPORT_*"}}. Each saved source below prints its own exact prefix, and the variables that system reads.

They are read when a run starts, not when you save, so changing one takes effect on the next run. A variable the server's process cannot see does not exist as far as the import is concerned: setting it in your own shell does nothing unless tix was started from that shell.

What the mapping file does

It is a YAML file, and every source needs one: a run with no mapping is refused before a single record is read. It says which tix project the records land in, which field on each record is its stable identifier, and what each external field becomes here.

It maps external statuses onto the states of that project's workflow, and a status it names that the workflow does not define is refused up front, naming the offending entry, with nothing written. External fields you assign to a custom field are created as real field definitions on the project. Fields the mapping does not name are preserved into custom fields rather than dropped, unless the mapping turns that off.

The identity section is what makes a re-import safe. Its updated_at field is also how an incremental run knows what is new, and, when you name no explicit version field, doubles as the version a record is compared against.

Dry run, and what a second run does

A dry run reads the source and reports exactly what a real run would create, update and skip, with a reason for every skip. It writes nothing at all: no tasks, no custom field definitions, no audit entries, and it does not move the source's cursor. It also does not appear in the run history, because nothing happened.

A second run is a refresh, not a second import. For each record, a task that already carries an external reference for that system and identifier is updated in place; one whose external version still matches the stored one is skipped as unchanged; anything with no reference yet is created. Titles, bodies and statuses are overwritten from the source, custom field values are merged over what is there, and tags are added but never removed.

Each source keeps a cursor, the watermark of the last record it committed, so a normal run fetches only what changed since. It moves forward in the same transaction as the records it covers, so a run that fails part way leaves it at the last page that did commit, and re-running picks up from there rather than starting over.

Tick Full to ignore the cursor and reconsider every record at the source. Note that a Full run starts from no cursor, so one that fails before committing a page leaves the source with no cursor at all: the next run then reads everything, which is slower but loses nothing. The Runs tab shows where each source's cursor stands.
