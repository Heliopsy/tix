How a run works

A source A name and a system, and nothing else: no url, no file path, no credential. Those live in environment variables on the machine running tix, read when a run starts rather than when you save, so changing one takes effect on the next run and none of them can reach a snapshot, an audit entry or a log line.
A mapping file Required: a run without one is refused before a single record is read. The YAML says which project the records land in, which field identifies them, and what each external field becomes here. A status it names that the project's workflow does not define is refused up front, with nothing written.
What a run writes Tasks in the project the mapping names, attributed to a System actor rather than to you, and ordinary in every other way. Each one carries an external reference recording where it came from and the version it was at, which is what makes a second run a refresh instead of a second copy.
Dry run Reports exactly what a real run would create, update and skip, with a reason for every skip, and writes nothing at all: no tasks, no field definitions, no audit entries, and it leaves the cursor where it was. It does not appear in the run history, because nothing happened.
The cursor, and Full Each source remembers the last record it committed, so an ordinary run fetches only what changed since and a run that fails part way resumes from the last page that committed. Full ignores the cursor and reconsiders every record at the source. The Runs tab shows where each cursor stands.
