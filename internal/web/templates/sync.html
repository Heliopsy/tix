{{t "How a run works"}}

{{t "A source"}} {{t "A name, a system, and what the form stores on it: the settings, the mapping document and the credentials. A stored value wins over its environment variable on the server, and one left empty is read from that variable when a run starts. Credentials are sealed with the server's key and never shown, audited or logged."}}
{{t "A mapping"}} {{t "Required: a run without one is refused before a single record is read. The YAML says which project the records land in, which field identifies them, and what each external field becomes here. A status it names that the project's workflow does not define is refused up front, with nothing written."}}
{{t "What a run writes"}} {{t "Tasks in the project the mapping names, attributed to a System actor rather than to you, and ordinary in every other way. Each one carries an external reference recording where it came from and the version it was at, which is what makes a second run a refresh instead of a second copy."}}
{{t "Dry run"}} {{t "Reports exactly what a real run would create, update and skip, with a reason for every skip, and writes nothing at all: no tasks, no field definitions, no audit entries, and it leaves the cursor where it was. It does not appear in the run history, because nothing happened."}}
{{t "The cursor, and Full"}} {{t "Each source remembers the last record it committed, so an ordinary run fetches only what changed since and a run that fails part way resumes from the last page that committed. Full ignores the cursor and reconsiders every record at the source. The Runs tab shows where each cursor stands."}}
{{end}}
