Listings

What the task screen draws and what every listing puts on screen. Each control here is the same form that sits on the screen it affects — one form over one stored value, not a copy of it — so changing it in either place shows the same answer in both.

Task view

Whether Tasks draws its tasks as a list of rows or as a board of columns. It is the same tasks either way: the filter, the deadline window, the sort, the page and the project choice below are answered once and then drawn one way or the other. The board needs the selected projects to run the same workflow, and says so when they do not.

{{template "taskview-switch" .Data.Prefs.TaskView}}

Projects on the task screen

Which projects Tasks includes. Unticking one leaves its tasks out of the listing and off the board; it hides nothing from anybody else and withholds no record, since every task stays on its own screen and a project: filter naming it explicitly still finds it. A project created after you choose is shown without being ticked.

{{template "project-choices" .Data.Prefs.Projects}}

Columns

Which optional columns each listing puts on screen, listing by listing, because they are a separate choice per listing: the columns worth keeping on Tasks are not the ones worth keeping on API tokens. Each listing also offers this picker beside itself; it is the same form, so either place shows what the other stored. Every listing keeps the column naming its rows whatever you choose, so no record can be put out of reach, and hiding a column withholds nothing — every value stays on the record's own screen. Reset returns a listing to its shipped defaults, which is not the same as unticking everything.
